# 그래프의 노드 제목이 겹치지 않게 놓는 방법

## 다루는 질문

노드 수십 개짜리 연결 그래프를 크기가 정해진 화면에 그리면 제목이 서로 겹친다. Obsidian 그래프 뷰 같은 도구는 같은 데이터인데도 제목이 겹치지 않고 잘 퍼져 보인다. 무엇이 다르고, 화면 크기가 정해진 웹 페이지에서는 어떻게 놓아야 하나.

## 설명

### 힘 배치는 겹침을 풀지 못한다

힘 기반 배치(force-directed layout)는 노드끼리 밀고 링크가 당기는 평형을 찾을 뿐, 제목 상자의 크기를 모른다. 이상적인 노드 간격 k는 대략 `√(면적 / 노드 수)`에 비례한다. 제목 한 줄의 폭이 k보다 길면 이웃한 노드 둘의 제목은 처음부터 겹치게 되어 있다. 데스크톱 한 화면에 노드 수십 개를 놓는 경우가 보통 이 조건에 걸린다.

Obsidian이 다르게 보이는 이유는 힘 계산이 아니라 **캔버스가 화면에 갇혀 있지 않기 때문**이다. 링크 거리를 넉넉히 두고 무한 캔버스에 펼친 뒤, 사용자가 줌으로 보고, 축소했을 때는 제목을 감춘다. 같은 데이터를 무대 크기에 맞춰 축소하면 제목이 다시 겹친다.

무대 안에서 제목을 전부 보이려면 공간이 얼마나 필요한지는 제목 상자 면적의 합을 무대 면적과 비교해 보면 된다. 상자 면적이 무대의 절반 가까이 차지하면 상자끼리 밀어내는 후처리로도 겹침이 남고, 캔버스를 두 배쯤 키워야 사라진다. 즉 "다 보이면서 안 겹치는" 화면은 그만한 캔버스와 줌이 있을 때만 성립한다.

### 지도 제작처럼 놓는다

화면 크기를 못 바꾼다면 제목 쪽을 지도 제작(cartographic labeling)의 표준 방식으로 놓는다.

1. **자리 후보를 여러 개 둔다.** 제목마다 아래·위·오른쪽·왼쪽 네 자리를 후보로 두고 비어 있는 첫 자리를 쓴다. 한 자리만 고정하면 이웃끼리 같은 방향으로 밀려 겹친다.
2. **우선순위대로 먼저 놓는다.** 선택된 노드 → 허브 → 연결이 많은 순. 먼저 놓인 제목이 자리를 잡고 뒤 제목이 피한다.
3. **자리가 없으면 숨긴다.** 억지로 겹쳐 그리지 않는다. 숨은 제목은 확대하거나 호버하면 나타난다.
4. **노드 원도 장애물로 본다.** 제목이 다른 노드 위에 얹히지 않게 원의 상자도 충돌 검사에 넣는다.
5. **화면 밖 자리는 쓰지 않는다.** 무대 경계를 벗어나는 후보는 건너뛴다. 가장자리 노드의 제목이 잘리는 문제를 막는다.

이 탐욕적(greedy) 배치는 순서에 의존한다. 앞에서 놓인 제목이 뒤의 자리를 막으면 뒤는 그냥 숨는다. 그래서 **호버는 배치에 끼워 넣지 않는다.** 호버한 노드를 우선순위 앞으로 당기면 그 순간 남의 제목까지 자리를 바꿔 화면이 튄다. 호버는 이미 보이는 제목이면 그대로 두고 맨 위로만 올리고, 숨어 있던 제목이면 그때만 빈자리에 얹는다.

### 확대해도 글자는 그대로

SVG에서 장면 전체를 `transform="scale(s)"`로 확대하면 제목도 같이 커진다. 제목 층의 글자 크기와 테두리를 `1/s`배로 다시 지정하면 노드와 선은 커지고 글자는 화면에서 항상 같은 크기를 유지한다. 노드와 제목 사이 간격, 두 줄 제목의 줄 간격도 같은 비율로 되돌린다. 구글 지도처럼 지형은 커지고 글자는 그대로인 방식이다.

이 위에 **확대 시 노출**을 얹는다. 맞춤 배율보다 조금 커지면 노드 간격이 화면에서 넓어지므로, 같은 자리 후보 규칙으로 자리가 나는 제목을 더 보인다. 맞춤 상태에서는 우선순위 상위 몇 개만 보이다가 확대할수록 나머지가 차례로 나타나고, 충분히 확대하면 전부 겹침 없이 보인다.

## 예제와 적용 경계

- 맞춤 배율을 1로 두려면 무대의 픽셀 크기로 배치한다. 큰 좌표계에서 배치한 뒤 축소하면 글자만 작아지는 게 아니라 간격도 줄어 겹침이 늘어난다.
- 이웃이 열 개를 넘는 허브를 선택하면 맞춤 배율에서는 이웃 제목 일부만 놓인다. 나머지는 확대·호버와 옆 목록(참조·역참조)으로 보완한다.
- 첫 화면부터 자리가 나는 제목을 다 보이면 알고리즘상 겹침은 없어도 지도가 빽빽해 보인다. 어디까지 보일지는 알고리즘이 아니라 편집의 문제다.
- 더 가는 방법은 두 가지다. 제목 전체를 한 번에 놓고 비용을 최소화하는 전역 최적화(시뮬레이티드 어닐링 류)와, 제목을 노드에 용수철로 매달아 서로 밀어내고 연결선으로 잇는 힘 기반 라벨(ggrepel 류). 둘 다 정적 시각화에 맞고, 클릭마다 상태가 바뀌는 지도에서는 매번 다시 계산되며 결과가 흔들린다. 노드가 몇 배 늘어 탐욕법으로 숨는 제목이 많아질 때 검토한다.
- 노드 위치 자체를 바꿔도 되는 전용 화면(예: 한 노드의 이웃만 그리는 방사형 배치)에서는 제목 상자 크기만큼 노드를 밀어내는 후처리가 더 단순하다.
- 작은 함정 하나. 배치 상자를 SVG 요소 크기로 재면 안 된다. `<svg>`는 마운트 전 기본 크기(300×150)를 가지므로 CSS로 크기가 정해진 부모 상자를 재야 한다.

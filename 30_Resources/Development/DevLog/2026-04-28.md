### 부트 기동 실패 디버깅
- `DeploymentObservationFlow` 생성자의 **Parameter 8 bean 모호성** — `Executor` 타입에 4개 빈(`qraObservationExecutor`, `qraTimelineExecutor`, `qraPodTerminationExecutor`, `argoCdObservationScheduler`)이 매칭되어 기동 실패
- 근본 원인: Spring 6.x가 파라미터명 보존을 위해 컴파일러 `-parameters` 플래그를 요구 → `JavaCompile` 태스크에 플래그 추가로 해결 방향 확정

```gradle
tasks.withType(JavaCompile).configureEach {
    options.compilerArgs.add('-parameters')
}
```

## 학습 & 인사이트

- **Spring 6.x + DI 모호성**: 같은 타입(`Executor`) 빈이 여러 개면 파라미터명으로 구분되는데, `-parameters` 컴파일 플래그가 없으면 이름이 소실되어 "single bean but N found" 로 터진다. 멀티모듈 이관 시 빌드 옵션까지 함께 옮겨야 한다는 교훈.
- **이관 = 스코프 결정의 연속**: Gen REST(개발자 테스트용), NotificationProxy처럼 "옮기지 않는다"를 명시적으로 결정하고 후속 이슈 생성 여부까지 끊는 게 마이그레이션 잡음을 줄인다.
- **flyway는 단일 파일 + 멱등성**: 분할보다 통합 + 멱등 패턴이 이관 스크립트 관리에 유리.
- **온보딩 문서는 선형성이 생명**: nats 등 부가 맥락이 앞에 끼면 첫 독자에게 혼란. qra 가이드의 "순서대로 따라하면 됨" 포맷이 이관 후에도 정답.
- **외부 이미지 공급 리스크**: bitnami/kafka 유료화처럼 베이스 이미지가 사라지면 로컬 테스트가 깨진다 — `bitnamilegacy` 같은 대체 경로 확보 필요.

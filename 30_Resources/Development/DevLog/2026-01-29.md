# 2026-01-29 DevLog

## QRA-POC (GitOps 배포 오케스트레이션 플랫폼)

### 로컬 개발 환경 구성

- **Docker Compose 개발 환경 설정**
  - PostgreSQL 16.6, Kafka 3.9 (KRaft mode), Kafka UI 구성
  - Zookeeper 없는 KRaft 모드로 Kafka 클러스터 구성
  - Bitnami 이미지 기반 안정화 버전 사용

- **Gitea Git 서버 설정**
  - Gitea 초기 설정 및 리포지토리 생성
  - SSH/HTTP 접근 구성

- **ArgoCD 연동**
  - k3d 클러스터에 ArgoCD 설치 확인
  - Gitea와 ArgoCD 연동 (Repository 등록)
  - 샘플 애플리케이션 배포 테스트 완료
  - ArgoCD 앱 상태 및 k8s 배포 확인

- **로컬 개발 환경 가이드 문서화**
  - `docs/gitops-local-dev-guide.md` 작성
  - Minikube/k3d 기반 환경 구성 가이드 포함

### ArgoCD API 연동 구현

- **qra-feature 모듈에 ArgoCD 클라이언트 구현**
  - Spring WebFlux WebClient 기반 API 클라이언트
  - Resilience4j Retry/CircuitBreaker 적용
  - 5초 폴링 방식 상태 모니터링

- **구현된 컴포넌트**
  - `ArgoCdProperties` - 설정 프로퍼티
  - `ArgoCdConfig` - WebClient Bean + Connection Pool
  - `ArgoCdClient` - API 호출 (getApplication, getResourceTree, syncApplication)
  - `ArgoCdWatcher` - 5초 폴링 스케줄러, 10분 타임아웃
  - `ArgoCdService` - 비즈니스 로직 레이어

- **DTO 클래스**
  - ArgoApplication, ArgoStatus, ArgoSyncStatus
  - ArgoHealthStatus, ArgoResourceTree, ArgoResourceNode
  - ArgoSyncRequest

- **예외 처리**
  - ArgoCdException, ArgoCdUnavailableException

- **테스트**
  - WireMock 기반 단위 테스트 (ArgoCdClientTest)
  - 전체 빌드 성공 확인

### 상태 매핑

| ArgoCD Status | DeployState |
|--------------|-------------|
| sync=Synced, health=Healthy | `Deployed` |
| health=Degraded/Missing | `Failed` |
| 10분 타임아웃 | `Failed` |

## 학습 & 인사이트

- **KRaft 모드**: Kafka 3.3+에서 Zookeeper 없이 자체 메타데이터 관리 가능
- **Resilience4j**: Spring Boot 3 호환, Reactor 지원으로 WebClient와 잘 통합됨
- **ArgoCD API**: `/api/v1/applications/{name}` 엔드포인트로 상태 조회, `sync.status`와 `health.status` 조합으로 배포 상태 판단

## 학습 & 인사이트

- **Spec-Drilling → Implement → Review 파이프라인의 정착**: 한 주 안에 `/spec-drilling` → `/implement-issue` → `/review-implement` 흐름을 다수 이슈(#7, #8, #13, #14, #15)에 일관되게 적용. 의식적 워크플로우가 자동화 단계로 넘어가는 신호.
- **테스트 race는 production race가 아니다**: Outbox publish + SSE 시그널 race 사례 — 같은 race 같지만 test design의 UI 게이트 누락이었음. 테스트 실패를 production 버그로 오인하지 않으려면 **production이 의지하는 시퀀스를 테스트도 그대로 따르는지** 먼저 검증해야 한다.
- **반복 실행 → 슬래시 커맨드화의 자연스러운 진화** (메타): 05-21 `full-lifecycle.sh` 첫 실행 → 05-22 `/full-lifecycle-e2e` 커맨드 + `fixture.sh` 정리. 같은 작업을 3번 이상 반복하면 자동화로 끌어올린다는 패턴.
- **큰 분석은 주말 시간을 활용** (자기관찰): 05-23 deployment 리스크 분석은 평일 이슈 처리와 다른 결의 작업 — 평일에는 이슈 단위로 좁게, 주말에는 도메인 전체로 넓게 보는 리듬.
- **W20 → W21 dogfooding 시간차 회로 완성** (인과): W20 05-14에 신규 생성한 `spec-drilling` 스킬이 W21 첫 주에 즉시 본격 활용 (#7, #8, #13, #14, #15). 도구를 만들고 다음 주에 자기 소비 — **자기 도구의 실효성을 1주 안에 검증하는 사이클**.
- **주말 자기 검토 패턴의 cross-week 반복** (자기참조): W17 04-26 일요일 DDD 경계 검토 → W21 05-23 토요일 deployment 리스크 분석. 평일 빠른 처리 + 주말 느린 사고의 리듬이 4주 단위로 재현됨.

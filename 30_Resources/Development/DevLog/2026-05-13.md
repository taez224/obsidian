### 이슈 #4 (US-1.2) — 구독 시점 Secret 동적 입력
- `SubscribeCommand.subscriptionSecrets` **null 의미론 확정**: `subscribe`라는 이름이지만 실제로는 기존 구독이 있으면 재설치/갱신(upsert)도 처리 → **null = 보존, [] = clear** (PATCH 의미론). create/replace였다면 null=보존을 두지 않았을 것
- 검증 약점 발견(adversarial review): `SubscriptionPvsFlow` 가 `subscriptionSecrets` 를 "실재하는 Drama version인지"만 검증하고 **이번 구독의 `rebuiltTargets` 에 포함되는지는 미검증** → 범위 밖 시크릿 주입 우회 가능
- Secret 모델 enum/타입 정리: `SecretScope` enum 도입, `catalogVersionId` → **`versionId`** 로 단순화, `packageType` 수용 여부 검토
- flyway 컬럼명을 **현재 코드 구현에 맞게** 수정(SubscriptionSecrets 래퍼 제거에 맞춰)
- `runtimePrerequisites` 정책을 `DramaDvpFlow` 로 **중앙화**(`2c25fb71a`), admin 흐름에도 동일 정책(D1-A) 적용

### 설계 난점 (아키텍트 관점 논의)
- **버전업/upgrade 시 시크릿 재입력 문제**: 구독 이후 버전업마다 시크릿을 하나하나 다시 넣는 건 부자연스러움 → latest 메타 carry-over UX, secret 전용 endpoint 이슈화, 그리고 시크릿을 **컬럼이 아니라 별도 테이블로 분리**할지 스토리지 진화 논점 도출

## 학습 & 인사이트

- **`subscribe`라는 이름에 속지 마라 — 의미론은 동작이 정한다**: 커맨드 이름이 subscribe여도 실제로 upsert(재설치/갱신)를 처리하면 `null = 보존`, `[] = clear` 라는 PATCH 의미론이 맞다. 이름만 보고 create/replace로 가정하면 "보존"을 빠뜨려 기존 시크릿을 날린다.
- **존재 검증 ≠ 범위 검증**: `subscriptionSecrets` 가 "실재하는 Drama version인가"만 보면, 이번 요청 범위(`rebuiltTargets`) 밖의 시크릿이 끼어드는 걸 못 막는다. 입력 검증은 "유효한가"를 넘어 **"이 요청에 속하는가"** 까지 봐야 우회를 막는다.
- **프론트가 백엔드에 없는 타입을 먼저 만들면 contract drift**: `SubscriptionSecretEntry` 처럼 프론트가 임의 타입을 선창하면 백·프론트가 갈라진다. 공용 타입(accent `IdNameValueList`)이나 ADR 합의를 **먼저 확인**하고 만드는 게 정합 비용을 줄인다.
- **디자인 기준점을 잘못 잡으면 임시방편이 표준이 된다**: gallery-view·plaza가 "개발자 임시 디자인"임을 모르고 기준으로 삼으면 임시 UI가 컨벤션으로 굳는다. 정식 디자인이 적용된 사례(bro)나 엔터프라이즈 레퍼런스를 기준으로 삼고, 선례 없는 패턴(stepper)은 의식적으로 개척해야 한다.
- **시크릿 스토리지는 "라이프사이클"이 모델을 정한다**: 첫 구독만 보면 컬럼 JSON으로 충분하지만, 버전업마다 재입력을 강요하면 UX가 깨진다. carry-over·전용 endpoint·별도 테이블 같은 선택은 **버전업/해제까지 포함한 라이프사이클**을 그려야 결정할 수 있다.
- **같은 Secret 이름을 두 역할에 매핑하면 충돌한다**: `vizend-flyway-secret` 을 admin pre-prep 자산이자 Bootstrap 출력으로 동시에 쓰면 multi-Kollex 환경에서 collision이 난다. credential tier는 이름·ns 단위로 명확히 갈라야 한다.
- **반복 작업은 스킬로 박는다**: 버전업 + CHANGELOG 갱신 같은 정형 작업은 `release-bump` 처럼 스킬화하면 휴먼 에러(버전 누락)를 줄인다. 단 CHANGELOG는 장황체가 아니라 짧은 스타일이 읽힌다.

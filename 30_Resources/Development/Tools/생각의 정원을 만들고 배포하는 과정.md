# 생각의 정원을 만들고 배포하는 과정

이 사이트는 Obsidian에 쓴 노트를 웹에서 읽을 수 있도록 만든 개인 위키입니다. 기록은 노트 앱에서 이어가고 사이트에서는 그 내용을 읽을 수 있습니다. 노트를 수정할 때마다 웹페이지용 원고까지 고치지 않도록 구성했습니다.

## 노트 하나를 고치면 사이트에도 반영되도록

Astro는 빌드할 때 미리 정해둔 공개 규칙에 맞는 Markdown 노트를 자동으로 읽어 웹페이지와 검색·연결 데이터를 만듭니다. 만들어진 정적 파일은 GitHub Pages에서 제공합니다.

본문과 제목·요약·링크는 Obsidian 노트에서 관리하고, 웹페이지와 카드의 모양은 사이트에서 관리합니다. 공개 규칙에 맞는 노트를 추가하거나 고치면 다음 빌드에 반영됩니다. 매번 공개할 파일을 따로 고르거나 페이지를 하나씩 등록하지 않아도 됩니다.

## 원본 보관과 웹 공개를 구분하기

자동으로 읽는 대상은 공개하도록 지정한 폴더의 노트입니다. 빌드는 제외 규칙을 적용하고, 블로그 폴더에서는 발행 상태나 연재 허브 여부도 확인합니다. 노트가 공개 조건에 맞는지는 이 규칙으로 판단하며, 원본은 Obsidian에 그대로 남습니다.

발행처에 따른 표시 규칙도 있습니다. 넥스트리 기술 블로그에 기고한 글은 빌드가 발행처와 원문 주소를 확인해 제목·요약·원문 링크를 담은 소개 페이지로 만듭니다. 노트 사이의 연결은 유지하므로 관련 생각을 읽다가 원문으로 이동할 수 있습니다.

## 노트의 연결을 웹에서도 활용하기

Obsidian의 위키링크는 웹페이지의 링크로 바꾸고 참조·역참조와 생각 지도에도 사용합니다. 링크 목록을 따로 관리하는 대신 노트에서 맺은 관계를 여러 탐색 방식에 활용하는 구성입니다.

## 생성된 결과까지 확인한 뒤 배포하기

공개 노트나 사이트 코드의 변경을 기본 브랜치인 `main`에 push하면 GitHub Actions가 테스트와 빌드를 실행합니다. 이 과정이 통과해야 새 결과물을 GitHub Pages에 배포합니다.

빌드 과정에는 생성된 파일을 검사하는 단계도 있습니다. 검사 스크립트가 페이지와 검색 데이터, 공유 이미지 등을 확인하고, 문제가 발견되면 새 배포로 넘어가지 않습니다.

공유할 때 보이는 이미지의 생성과 캐시는 [[정적 사이트에서의 OG 카드와 방문자 카운팅]]에 따로 정리했습니다.

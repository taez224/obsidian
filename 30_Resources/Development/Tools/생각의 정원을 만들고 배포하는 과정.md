# 생각의 정원을 만들고 배포하는 과정

> [!summary] 핵심 구조
> Obsidian에 쓴 노트가 바로 웹페이지가 된다. 노트와 웹페이지 원고를 따로 두지 않고, vault의 Markdown을 Astro가 공개 규칙에 따라 사이트로 변환한다.

## 공개 규칙과 원본

공개 대상은 설정한 폴더와 발행 상태로 결정한다.Obsidian 원본 노트 중 사이트 공개 기준을 통과한 것만 내보낸다.

회사 기술 블로그에 기고한 글은 이 사이트에 전문을 올리지 않고 제목·요약·원문 링크를 담은 소개 페이지로 전환한다.

## 노트 연결과 웹 탐색

Obsidian의 위키링크는 웹페이지 링크로 바뀌고, 참조·역참조와 생각 지도에도 사용한다. 노트에서 맺은 관계를 여러 탐색 방식에 활용한다.

## 빌드와 배포

사이트 저장소의 `main`에 코드를 push하면 GitHub Actions가 Obsidian 저장소를 받아 테스트와 빌드를 실행한다. 생성된 결과를 검사해 문제가 없을 때 GitHub Pages에 배포한다.

Obsidian 저장소만 수정해 push한 경우에는 다음 예약 빌드에 반영된다. 바로 반영하려면 사이트 저장소에서 배포 워크플로를 수동 실행한다.

공유 이미지 생성과 캐시는 [[정적 사이트에서의 OG 카드와 방문자 카운팅]]에서 따로 다룬다.

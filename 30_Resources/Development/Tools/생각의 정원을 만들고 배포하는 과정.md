# 생각의 정원을 만들고 배포하는 과정

이 사이트는 Obsidian에 쓴 노트를 웹에서 읽을 수 있도록 만든 개인 위키입니다. 기록은 노트 앱에서 이어가고 사이트에서는 그 내용을 읽을 수 있습니다. 노트를 수정할 때마다 웹페이지용 원고까지 고치지 않도록 구성했습니다.

## 노트 하나를 고치면 사이트에도 반영되도록

전체 흐름은 단순합니다. Obsidian의 Markdown 노트에서 공개 대상을 고르고 Astro가 웹페이지와 검색·연결 데이터를 생성합니다. 만들어진 정적 파일은 GitHub Pages에서 제공합니다.

Astro에 노트를 읽어오는 로더를 붙여 제목, 요약, 링크 같은 정보를 페이지에서 사용할 수 있게 했습니다. 본문과 메타정보는 노트에 두고 글 목록이나 카드의 모양은 사이트에서 관리합니다. 기존 공개 규칙에 맞는 노트라면 새로 추가할 때 페이지를 하나씩 등록할 필요가 없습니다.

## 원본 보관과 웹 공개를 구분하기

노트 앱에 있다고 해서 모두 사이트에 표시하지는 않습니다. 공개할 폴더와 제외할 자료를 설정하고 블로그 글은 발행 상태도 확인합니다. 이 규칙은 웹사이트에 내보낼 내용을 정하며 원본 노트나 Git 이력을 지우는 방식은 아닙니다.

글에 따라 공개하는 정도도 다릅니다. 넥스트리 기술 블로그에 기고한 글은 가든에 제목과 요약, 원문 링크만 남깁니다. 반면 노트 사이의 연결은 유지해 관련 생각을 읽다가 원문으로 이동할 수 있도록 했습니다.

## 노트의 연결을 웹에서도 활용하기

Obsidian의 위키링크는 웹페이지의 링크로 바꾸고 참조·역참조와 생각 지도에도 사용합니다. 링크 목록을 따로 관리하는 대신 노트에서 맺은 관계를 여러 탐색 방식에 활용하는 구성입니다.

## 생성된 결과까지 확인한 뒤 배포하기

노트나 사이트 코드의 변경을 GitHub에 올리면 GitHub Actions가 테스트와 빌드를 실행합니다. 이 과정이 통과해야 새 결과물을 GitHub Pages에 배포합니다.

페이지가 생성됐다는 사실만으로 방문자가 제대로 읽을 수 있다고 보기는 어렵습니다. 그래서 생성된 파일을 다시 열어 페이지 주소와 검색 데이터, 공유 이미지 등을 검사합니다. 검사에서 문제가 발견되면 새 배포로 넘어가지 않습니다.

공유할 때 보이는 이미지의 생성과 캐시는 [[정적 사이트에서의 OG 카드와 방문자 카운팅]]에 따로 정리했습니다.

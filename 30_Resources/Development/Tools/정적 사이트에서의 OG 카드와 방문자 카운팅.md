# 정적 사이트에서의 OG 카드와 방문자 카운팅

## 다루는 질문

서버 없는 정적 사이트에서 글마다 다른 `og:image`를 어떻게 만드는가. 빌드 때 그린 이미지를 캐시한다면 무엇을 키로 삼아야 코드 변경이 반영되고, 어떤 상황이 캐시를 망가뜨리는가. 같은 조건(서버 없음, 쿠키 없음)에서 방문은 어떻게 세는가.

## 설명

### 카드는 빌드 때 SVG를 PNG로 굽는다

SVG 문자열을 직접 조립하고 `@resvg/resvg-js`로 PNG를 만든다. 1200×630 캔버스에 배경, 워드마크, 제목, 메타 줄, 장식을 `<text>`·`<circle>`·`<line>`으로 쓴다. 템플릿 엔진도 헤드리스 브라우저도 필요 없고 CI 러너에서 그대로 돈다. PNG가 필요한 이유는 SVG를 카드로 받는 플랫폼이 거의 없어서다.

파일은 Astro 정적 엔드포인트가 만든다. `pages/og/[...slug].png.ts`가 `getStaticPaths`로 노트마다 경로를 내고 `GET`이 PNG 버퍼를 돌려주면 빌드 결과에 `og/<종류>/<슬러그>.png`가 생긴다. 노트 페이지는 자기 카드 주소를 `og:image`에 넣고, 홈이나 목록처럼 노트가 아닌 페이지는 사이트 카드 한 장을 공유한다.

제목은 정해진 줄 수(세 줄) 안에 들어가는 가장 큰 글자 크기를 고르고, 그래도 넘치면 마지막 줄을 줄임표로 자른다. 글자 폭은 한글·영숫자·기타 세 부류의 평균 폭으로 어림한다. 실제 폰트 계측 없이도 카드에서는 어긋남이 보이지 않았다. 카드 오른쪽에는 그 노트의 로컬 그래프(중심과 이웃 최대 8개)를 주제 색으로 얹는다. 같은 템플릿이지만 글마다 모양이 달라진다. 배치 코드는 [[그래프의 노드 제목이 겹치지 않게 놓는 방법]]의 것을 그대로 쓴다.

### 폰트는 내려받아 캐시한다

CI 이미지에는 한글 폰트가 없다. resvg에 시스템 폰트를 쓰지 않도록 하고 OTF 파일을 직접 넘긴다. woff2는 읽지 못하므로 정적 OTF가 필요하다. 명조 제목은 [Noto Serif KR](https://github.com/notofonts/noto-cjk)의 한국어 서브셋(약 8MB), 고딕 메타는 [Pretendard](https://github.com/orioncactus/pretendard) 정적 인스턴스(약 1.5MB)를 쓴다.

저장소에 넣기엔 커서 첫 빌드 때 내려받아 `node_modules/.cache` 아래에 둔다. CI에서는 이 디렉터리를 캐시해 매번 받지 않는다. 받다가 끊긴 파일이 캐시로 남지 않도록 임시 파일에 쓴 뒤 이름을 바꾸고, 크기가 하한보다 작으면 다시 받는다. 그래도 받지 못하면 로컬에서는 시스템 폰트로 그리고 경고만 내지만, CI에서는 빌드를 실패시킨다. 엉뚱한 폰트로 그린 카드를 배포하는 것보다 이전 배포를 남기는 쪽이 낫다.

### 렌더 결과는 캐시하되 키는 최종 SVG로

카드가 백 장 단위면 매 빌드에 몇 초가 든다. 노트 하나를 고칠 때마다 전부 다시 그릴 이유가 없어서 PNG를 `node_modules/.cache` 아래에 캐시하고, CI에서도 이 디렉터리를 실행마다 저장해 다음 실행이 복원한다.

캐시 키는 **최종 SVG 문자열 + 폰트 파일의 이름·크기 + resvg 버전**의 해시다. 제목·날짜·이웃 같은 입력값으로 키를 만들면 템플릿이나 제목 접기 코드를 고쳐도 옛 PNG가 그대로 나온다. 카드를 바꾸는 코드는 전부 SVG에 드러나므로 SVG를 해시하면 이 문제가 없고 수동 버전 상수도 필요 없다. SVG에 드러나지 않는 것은 폰트와 렌더러뿐이라 그 둘만 키에 더한다.

캐시가 망가지는 경우 셋을 막는다.

- 잘린 파일. 쓰는 도중 빌드가 죽으면 0바이트 PNG가 남는다. 읽을 때 PNG 서명과 IHDR의 폭·높이를 확인해 아니면 다시 그리고, 쓸 때는 임시 파일에 쓴 뒤 이름을 바꾼다.
- 폴백 렌더. 폰트가 없어 시스템 폰트로 그린 결과는 캐시에 넣지 않는다. 넣으면 폰트가 돌아온 뒤에도 그 카드가 계속 나온다.
- 무한 증가. 노트를 고칠 때마다 새 파일이 생기고 옛 파일은 쓰이지 않는다. 적중한 파일은 mtime을 갱신하고, 빌드 시작 때 일정 기간(14일) 넘게 안 쓴 파일을 지운다.

산출물 검사도 카드 파일의 존재만 보지 않고 실제 1200×630 PNG인지 본다.

### 플랫폼 캐시는 별개다

배포 뒤에는 카드 주소가 `image/png`로 열리고 페이지의 `og:image`가 그 주소인지 보면 된다. 이미 공유한 링크는 플랫폼이 옛 이미지를 한동안 유지한다. 빌드 캐시와 무관하므로 플랫폼의 공유 디버거에서 다시 긁게 해야 한다.

### 방문자 집계는 Umami Cloud로

정적 호스팅에는 서버 로그가 없다. 쿠키 없이 가능한 방문자 집계 도구 중 Umami Cloud를 골랐다. Hobby 플랜은 무료이고 월 10만 이벤트(페이지뷰 1회 = 1이벤트), 웹사이트 1개, 보관 6개월이다([2026-09-06 요금 페이지](https://umami.is/pricing) 기준).

- 스크립트 태그는 사이트 설정에서 웹사이트 ID를 읽어 넣는다. ID가 비어 있으면 넣지 않는다.
- `data-domains`에 배포 도메인을 적으면 로컬 미리보기에서는 집계되지 않는다.
- 본인 방문 제외는 IP가 아니라 브라우저 저장소로 한다. Umami 스크립트는 전송 전에 `localStorage`의 `umami.disabled`를 본다. 기기·브라우저마다 한 번씩 심어야 하므로, 주소 쿼리(`?stats=off`)를 읽어 값을 심고 확인 문구를 띄우는 짧은 인라인 스크립트를 두면 편하다.

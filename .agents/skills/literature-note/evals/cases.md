# 참고노트 귀속 구분 평가

스킬을 보완하거나 검증할 때만 사용한다. 일반 참고노트 작성에 평가·확인 질문을 추가하지 않는다. 실행과 판정은 기존 [공통 평가 절차](../../taez-insight-blog-writer/evals/cases.md)를 따른다.

[real-cases.json](real-cases.json)은 기존 참고노트에 기록된 원문 발췌·사용자 반응과 AI 분석 노트의 채택 표시를 고정한 실제 자료 기반 사례다. 요청은 평가용으로 재구성했으며 당시 대화의 재현은 아니다. `provenance`의 커밋과 발췌를 기준으로 사용하고, 원문이 바뀌어도 기존 입력을 덮어쓰지 않는다.

| ID | 확인할 판단 |
| --- | --- |
| short-creativity-reaction | 짧은 공감을 훈련 계획·취향·개발 적용에 대한 새 사용자 주장으로 늘리지 않는가 |
| partial-glue-work-agreement | 성과 측정·정체감에 대한 부분 공감과 저자의 일반적인 회피 권고를 구분하는가 |
| rich-role-reaction | 풍부한 반응의 자기 분류·비유·단서를 중립 요약으로 줄이지 않는가 |
| adopted-ai-candidates | 사용자가 체크한 AI 후보는 다시 묻지 않고 주장으로 쓰며 체크하지 않은 후보는 구분하는가 (permanent-note) |

`short-creativity-reaction`과 `rich-role-reaction`은 반응을 부풀리는 실패와 깎는 실패를 짝으로 본다. `adopted-ai-candidates`는 채택한 AI 후보를 쓰지 못하는 실패와 채택하지 않은 후보를 쓰는 실패를 한 사례에서 함께 본다. 한쪽 사례만 통과했다면 개선으로 보고하지 않는다.

- 입력은 기존 노트에 기록된 발췌·요약 범위다. 웹 원문 전체나 자막의 정확성, 반응의 최초 작성자를 확인했다고 보고하지 않는다. 기록된 사용자 반응을 입력으로 사용했다는 범위까지만 말한다.
- `prompt`와 `artifact`, 해당 버전의 스킬·런타임 참조만 실행자에게 준다. `selection`의 반응 범위·편집상 관찰과 검사 기준은 판정자에게만 준다. 자료 내용·사용자 반응·채택하거나 채택하지 않은 AI 제안이 어디에 귀속됐는지 실제 완성안으로 판정한다.
- 각 사례는 별도 세션에서 읽기 전용으로 실행한다. 원문 확보·중복 확인·저장 경로는 평가에서 고정하거나 제외한 조건이므로, 이 실행을 웹 수집·저장·검색까지의 전체 검증으로 보고하지 않는다.
- 실패가 없으면 본문 동작을 바꾸지 않는다. 실패가 드러나 수정했다면 같은 고정 사례와 정상 사례를 같은 조건으로 다시 실행한다. 단일 버전 관찰과 변경 전후 비교를 구분한다.
- 결과와 실행자·판정자의 상세 출력은 임시 폴더나 `_workspace/`에 둔다. 합성 오답으로 판정 기준을 확인할 수 있지만 실제 실패나 실제 참고노트 사례로 섞지 않는다.

이 사례를 위해 추가 사용자 평가·반응 설명·AI 가설 채택을 요구하지 않는다. 입력에 이미 있는 반응을 그대로 사용하고, 반복 실패나 원인이 분명한 결함만 기존 작성·대조 단계 안에서 보완한다.

# Literature note

읽은 외부 자료를 사용자가 반응한 대목 중심으로 `30_Resources/References/Articles/`에 참고노트로 남긴다. 참고노트는 자료 전체를 요약하지 않고 **흥미로웠던 대목, 동의하거나 의심한 부분, 내 경험·기존 생각과 연결되는 부분**만 남긴다([[Obsidian 운영 워크플로]] 참고노트 섹션이 정본). 목표는 원문을 대체하는 요약이 아니라, 나중에 승격·연결 판단의 재료가 되는 사용자의 반응 기록이다.

## 원칙

1. **무엇을 남길지는 사용자의 반응이 정한다.** 사용자가 언급하지 않은 부분은 한눈에 보기(abstract) 이상으로 펼치지 않는다. 에이전트가 중요하다고 본 대목은 노트가 아니라 대화에서 후보로만 제안하고, 사용자가 채택한 것만 넣는다.
2. **인용과 생각을 분리한다.** blockquote(`>`)는 원문의 실제 문장·발화(번역 포함)에만 사용하고 원문 위치(타임스탬프·헤딩·문단)를 함께 남긴다. 재구성한 예시는 `> [!example] 재구성한 예시` callout으로 표시한다.
3. **전문을 복제하지 않는다.** 원문은 `source` URL 또는 기존 클리핑이 정본이다.
4. **my_take는 사용자의 것이다.** 사용자가 밝힌 평가만 기록하고, 없으면 `""`로 둔다. 에이전트가 대신 지어내지 않는다.

## 절차

### 1. 원문 확보와 중복 확인

- `rg -n -F "<source URL>" 30_Resources/`로 기존 노트를 확인한다. Articles에 이미 있으면 새로 만들지 않고 보강을 제안한다.
- Clippings에 자료카드가 있으면 그 카드의 `source`와 메타데이터를 출발점으로 삼고 원문은 URL에서 다시 확보한다. 없으면 웹 문서는 `defuddle`, 유튜브는 자막 등으로 원문을 확보하고 **확보 방법과 한계**를 사용자 보고에 명시한다.

### 2. 사용자 반응 확인

노트를 쓰기 전에 사용자의 반응이 있는지 확인한다. 대화에 이미 반응(인상 깊은 대목, 동의·의심, 자기 경험과의 연결)이 있으면 그대로 재료로 쓰고, 없으면 짧게 묻는다 — 어떤 대목이 남았는지, 동의하거나 의심한 지점이 있는지. 질문은 1~2개로 제한한다.

- 반응이 전혀 없고 아직 읽지 않은 자료면 이 스킬을 쓰지 않고 `capture-reference-card`를 제안한다.
- 읽었지만 반응이 한 줄 평 수준이고 기존 클리핑이 있으면, 별도 노트 대신 클리핑의 `my_take`를 채우고 `status: read`로 갱신하는 쪽을 제안한다(`_property-schema.md`의 "참조용 보관").

### 3. 노트 작성

frontmatter는 `99_Templates/References/article-template.md`를 따른다. `published`(원본 공개일)를 확인해 기록하고, 확인할 수 없을 때만 비워 둔다. 사용자가 읽었으므로 `status: read`.

파일명은 `<제목 또는 자연스러운 번역> - <저자>.md` 형태를 권장하되 기존 Articles 파일명 관례를 따른다.

본문 구조:

```markdown
> [!abstract] 한눈에 보기
> <자료 전체를 관통하는 논지 2~3문장>

## 자료 정보

- 발표자/저자, 형식(분량), 원문 링크, 클리핑이 있으면 [[클리핑 노트]]

## 남긴 대목

> 원문 인용 (위치: 타임스탬프·헤딩 등)

- 내 생각: <이 대목에 대한 사용자의 반응>

<반응한 대목 수만큼 반복. 인용 없이 반응만 있으면 대목을 한 문장으로 요약하고 위치를 남긴다>

## 나의 해석

<자료 전체에 대한 사용자의 평가·비판·확장. 없으면 섹션 생략>

## 연관된 노트

- [[존재 확인한 노트]] - 연관 이유 한 줄
```

- 연관 노트는 `rg`(정확)와 QMD(의미)로 후보를 찾고, **링크 대상이 실존하는지 확인**한 뒤 이유 한 줄과 함께 넣는다. 억지 연결은 만들지 않는다.
- 기존 클리핑이 있으면 클리핑의 `status`를 `read`로 갱신하고 자료카드는 수집 이력과 원문 진입점으로 유지한다.

### 4. 원문 대조

초안을 쓴 뒤 확보한 원문과 대조해 어긋난 부분을 고치고 보고한다.

- `title`, `author`, `published`, `source`, 숫자, 고유명사가 원문과 일치하는가?
- blockquote가 실제 발화·문장의 번역이며 원문 위치를 추적할 수 있는가?
- 한눈에 보기(abstract)가 원문의 논지를 왜곡하거나 과장하지 않는가?
- 사용자의 반응이 저자의 주장처럼, 저자의 주장이 사용자의 생각처럼 쓰이지 않았는가?
- 내부 링크가 실제로 존재하고, 키워드 일치가 아니라 설명 가능한 관계를 가지는가?

### 5. 열고 보고하기

가능하면 다음 명령으로 참고노트를 연다.

```bash
obsidian open path="30_Resources/References/Articles/<파일명>.md"
```

- 저장 경로와 원문 확보 방법을 짧게 보고한다.
- 사용자의 반응 중 여러 맥락에서 재사용할 주장으로 발전할 수 있는 것이 보이면 `후속 검토 포인트`로만 보고한다. 승격은 `review-zettelkasten`·`permanent-note`의 몫이다.

## 경계

- 아직 읽지 않은 자료의 보관 요청은 `capture-reference-card`를 사용한다. 이 스킬로 전체 요약을 만들지 않는다.
- 대화 안에서 요약만 요청하고 저장 의사가 없으면 파일을 만들지 않는다.
- `01_Slipbox/`에 직접 쓰지 않는다. 승격·연결·MOC 판단은 `permanent-note`·`review-zettelkasten`의 몫이다.
- 책은 이 스킬 대상이 아니다 (`99_Templates/book-note.md`).
- Web Clipper나 `capture-reference-card`가 만든 Clippings 노트를 이 스킬 형식으로 재작성하지 않는다. 참고노트는 별도 파일로 만들고 클리핑은 링크한다.
- 원문에서 확인되지 않는 사실·인용을 만들지 않는다. 자동 자막의 고유명사 오류는 문맥으로 보정하되, 불확실하면 이름을 특정하지 않는다.

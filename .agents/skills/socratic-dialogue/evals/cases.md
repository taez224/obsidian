# 문답 종료 행동 평가

종료 처리나 주장 채택 기준을 바꿀 때만 읽는다. [cases.json](cases.json)은 모두 합성 대화이며 실제 사용자 경험이나 주장으로 인용하지 않는다.

| ID | 확인할 행동 |
| --- | --- |
| clear-current-claim | 이미 명료한 사용자 주장은 다시 묻지 않고 조건·유보를 보존해 정리한다. |
| unadopted-claim | 미채택 AI 가설을 결론으로 삼지 않고, 아직 모호한 사용자 주장만 짧게 확인한다. |
| explicit-stop | 명시적인 중단에는 마지막 질문도 생략하고, 미채택 가설과 저장 금지를 보존한다. |

실행 격리·변경 전후 비교·판정과 결과 보관은 기존 [공통 행동 평가 절차](../../taez-insight-blog-writer/evals/cases.md#실행과-판정)를 따른다. 별도 실행기를 만들지 않는다.

- 각 사례는 앞선 평가 맥락이 없는 읽기 전용 실행자에게 스킬 사본, `prompt`, `artifact`만 제공한다. 기대 행동과 이전 결과는 전달하지 않는다.
- `process_checks`는 실제로 읽은 경로와 도구 사용 기록으로, `result_checks`는 실제 응답으로 각각 판정한다. 응답 판정 때는 버전·실행자·스킬 경로를 가린다.
- 질문 개수나 특정 문구만 맞췄다고 통과시키지 않는다. 이미 한 답을 다시 요구하는지, 미채택 가설을 사용자 주장으로 바꾸는지, 조건과 중단 의사를 보존하는지를 본다.
- 변경 전후는 같은 사례·런타임·모델·도구 제한으로 비교한다. 한 번씩의 관찰로 일반적인 정확도나 개선율을 주장하지 않는다. 스킬 자체의 효과를 주장하려면 스킬 없는 기준선도 필요하다.
- 실제 응답·버전과 실행 경로·판정 근거는 `_workspace/` 또는 임시 폴더에 보관하고 커밋하지 않는다. 이 폴더에는 재실행할 입력과 기준만 둔다. 형식 검사는 행동 평가 통과로 세지 않는다.

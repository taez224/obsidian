# Capture reference card

아직 읽지 않은 외부 자료를 `30_Resources/References/Clippings/`에 알아보기 쉬운 Git-safe 자료카드로 포착한다. 카드에는 무엇을 어디서 발견했는지와 확인 가능한 최소 내용만 남기고, 전문 보관은 Git 추적 경계 밖으로 분리한다.

## 역할 경계

| 상태 | 저장 위치 | 담당 |
| --- | --- | --- |
| 아직 읽지 않은 외부 자료 | `References/Clippings/` | `capture-reference-card` |
| 읽고 반응을 남길 자료 | 기존 Clipping 갱신 또는 `References/Articles/` | `literature-note` |
| 여러 맥락에 재사용할 내 주장 | `01_Slipbox/` | `permanent-note` |

## 원칙

1. **출처와 최소 내용을 포착한다.** 원문 제목, `source`, 확인된 저자·발행일, 한국어 식별 문장, 사용자의 저장 맥락을 남긴다.
2. **요약은 확인한 만큼만 쓴다.** 도입·주요 절·결론을 충분히 확인했을 때 원문의 주장·방법·사례를 4~7개로 압축한다. 유료벽·로그인·불완전 추출로 근거가 부족하면 `## 내용 요약`을 생략한다.
3. **Git 추적 카드는 배포 가능한 범위로 제한한다.** 전문, 장문 번역, 연속된 긴 인용을 카드에 넣지 않는다. `source`가 URL 정본이므로 `## 원문`과 `[원문 보기]`도 만들지 않는다.
4. **원문의 말과 내 생각을 섞지 않는다.** 설명과 요약에는 평가·시사점·잠정 인사이트·주제 태그·연관 노트를 넣지 않는다.
5. **캡처 단계에서 지식 연결을 판단하지 않는다.** 정확한 URL 중복만 확인하고 QMD 검색, Slipbox 연결·승격 판단, 즉시 재색인은 하지 않는다.

## 절차

### 1. 요청을 라우팅한다

- URL만 받았거나 읽지 않은 자료를 보관하려는 요청이면 이 스킬을 사용한다.
- 자료를 읽고 인상 깊은 대목·동의·의심·경험 연결을 함께 말했다면 `literature-note`를 사용한다.
- 저장 의사 없이 요약·분석만 요청했다면 파일을 만들지 않는다.
- 개인 생각을 빠르게 남기려는 요청이면 `capture-fleeting-note`를 사용한다.

### 2. URL 중복을 확인한다

```bash
rg -n -F "<source URL>" 30_Resources/References
```

- 같은 URL의 Clipping이나 Article이 있으면 새 파일을 만들지 않고 기존 경로를 보고한다.
- 관련 자료를 찾기 위한 의미 검색은 하지 않는다.

### 3. 출처와 확인 가능한 내용을 수집한다

`defuddle parse <URL> --md` 등으로 제목, canonical URL, 저자, 공개일, meta description, 대표 이미지와 본문 접근 범위를 확인한다. 추출한 전문은 요약 근거로만 사용하고 Git 추적 카드에 복제하지 않는다.

- 확인되지 않는 `author`, `published`, `thumbnail`은 추측하지 않고 비우거나 생략한다.
- `description`은 제목·meta description·도입부에 근거한 한국어 식별 문장 1~2개로 쓴다. 자료의 중요성이나 활용법을 덧붙이지 않는다.
- 도입·주요 절·결론을 확인했으면 핵심 주장·방법·사례를 `## 내용 요약` 4~7개로 적는다.
- 유료벽·로그인·봇 차단·부분 추출로 사실 확인이 부족하면 메타데이터와 설명만 남기고 요약을 생략한다. 제목이나 검색 결과만으로 내용을 추론하지 않는다.
- canonical URL이 확인되면 `source`에 쓰고 그 URL도 중복 확인한다.

### 4. Git-safe 자료카드를 만든다

frontmatter는 `99_Templates/_property-schema.md`의 Articles & Clippings 섹션을 따른다.

```markdown
---
title: <원본 제목>
source: <canonical URL 또는 입력 URL>
author:
  - <확인된 저자>
published: <확인된 원본 공개일 또는 "">
created: <오늘>
description: <원문에 근거한 한국어 식별 문장 1~2개 또는 "">
thumbnail: <확인된 대표 이미지 URL, 없으면 속성 생략>
tags:
  - clippings
status: unread
my_take: ""
---

> [!note] 저장 맥락
> <사용자가 밝힌 저장 이유 — 없으면 callout 전체 생략>

## 내용 요약

- <충분히 확인한 핵심 주장·방법·사례 1>
- <충분히 확인한 핵심 주장·방법·사례 2>
- <충분히 확인한 핵심 주장·방법·사례 3>
- <충분히 확인한 핵심 주장·방법·사례 4>

## 함께 남긴 대목

> <사용자가 직접 지정한 짧은 인용 — 없으면 섹션 전체 생략>
```

- 사실 확인이 부족하면 `## 내용 요약` 전체를 생략한다.
- 파일명은 원문 제목을 자연스러운 한국어로 옮기고 파일명에 쓸 수 없는 문자만 정리한다. 원문 제목은 `title`에 그대로 보존한다.
- 사용자가 밝힌 저장 이유나 직접 고른 짧은 인용은 표현을 바꾸지 않는다.
- 저자를 확인하지 못하면 `author: []`로 둔다.

### 5. 개인용 원문 스냅샷은 분리한다

전문은 자동으로 저장하지 않는다. 사용자가 접근 권한이 있는 자료를 개인적으로 로컬 보관해 달라고 **명시적으로 요청한 경우에만** 다음 경로에 같은 파일명으로 저장한다.

```text
30_Resources/References/Clippings/_local-snapshots/<자료카드 파일명>.md
```

- 작업 전에 `.gitignore`가 `_local-snapshots/`를 제외하는지 확인한다.
- 로컬 파일에는 다음 최소 frontmatter를 두고, 그 아래에 원문 제목과 확보한 원문 언어의 Markdown 본문을 그대로 둔다.

```markdown
---
title: <원문 제목>
source: <canonical URL 또는 입력 URL>
author:
  - <확인된 저자>
published: <확인된 원본 공개일 또는 "">
created: <로컬 보관일>
card: "[[자료카드 파일명]]"
---

# <원문 제목>

<원문 Markdown 본문>
```

- 원문 전체를 callout이나 blockquote로 감싸지 않는다. 헤딩·표·코드 블록·이미지·인용 구조를 불필요하게 바꾸지 않는다.
- `description`, 내용 요약, `my_take`, `status`는 자료카드의 책임이므로 스냅샷에 반복하지 않는다.
- 추적 카드에는 로컬 파일 링크를 만들지 않는다. 다른 clone에서 죽은 링크가 되기 때문이다.
- `_local-snapshots/`는 QMD 연결 후보와 vault-lint 대상에서 제외한다.
- 기존 추적 카드에 전문이 있으면 로컬 파일 생성과 내용 확인을 먼저 마친 뒤 카드에서 전문을 제거한다.

### 6. 열고 보고한다

가능하면 다음 명령으로 자료카드를 연다.

```bash
obsidian open path="30_Resources/References/Clippings/<파일명>.md"
```

저장 경로, 한국어 파일명, 비어 있는 주요 메타데이터, 내용 요약 작성·생략 여부를 짧게 보고한다. 개인용 스냅샷을 요청받았다면 Git 제외 경로와 제외 확인 결과도 알린다. 스냅샷은 열지 않는다.

## 기존 Web Clipper 보관본 정리

사용자가 기존 Clipping 정리를 승인한 경우 다음 순서로 처리한다.

1. 기존 `title`, `source`, 저자·발행일, `status`, `my_take`, 사용자 메모를 보존한다.
2. 확인 가능한 한국어 `description`과 내용 요약 4~7개를 카드에 둔다. 확인이 부족하면 요약을 생략한다.
3. 본문의 중복 `## 원문` 링크를 제거한다.
4. 전문이나 장문 번역이 있으면 사용자의 로컬 보관 의사를 확인한다. 보관하기로 했다면 `_local-snapshots/`에 최소 frontmatter와 원문 Markdown 형식으로 먼저 복사하고 검증한 뒤 추적 카드에서 제거한다.
5. 사용자가 전문 제거만 요청했거나 로컬 보관을 원하지 않으면 체크포인트 또는 복구 가능한 Git 상태를 확인한 뒤 제거한다.

## 경계

- `01_Slipbox/`나 `30_Resources/References/Articles/`에 쓰지 않는다.
- `my_take`를 대신 작성하거나 `status: read`로 만들지 않는다.
- 원문 전문·장문 번역·연속된 긴 인용을 Git 추적 카드에 넣지 않는다. 공개 자료도 기본 규칙은 같다.
- 접근 제한 자료의 내용을 제목·검색 결과·주변 문맥으로 추정해 요약하지 않는다.
- 주제 태그, 관련 노트 링크, 발전 질문을 자동으로 추가하지 않는다.
- 사용자가 나중에 자료를 읽고 반응을 남기면 `literature-note`로 별도 참고노트를 만들고 이 자료카드를 출처로 링크한다.

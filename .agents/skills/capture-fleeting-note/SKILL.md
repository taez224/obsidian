# Capture fleeting note

떠오른 생각의 골든타임을 놓치지 않도록 최소한의 가공만 거쳐 `00_Inbox/`에 저장한다.

## 원칙

1. **속도가 완성도보다 중요하다.** 저장에 필요하지 않은 질문을 하지 않는다.
2. **원문은 해석하지 않는다.** 오타·음성 인식 오류만 바로잡고 주장, 사례, 감정의 결을 보존한다.
3. **AI 보충은 원문과 접어서 분리한다.** `AI 생성` 섹션의 접힌 callout에 사용자 원문에서 발전시킨 초기 해석을 적는다. 분석·가설·대응표·잠정적인 핵심 주장과 발전 질문을 포함할 수 있고 원문보다 길어도 되지만, 생각을 다시 펼치는 데 직접 도움이 되는 내용만 남긴다. 이는 사용자의 주장이나 검증된 참고자료가 아님을 표시한다. 외부 사실·인용·출처를 조사하거나 단정하지 않으며 링크 검색·태그 추천도 하지 않는다. 사용자가 원문만 저장해 달라고 했거나 의미 있는 보충이 없으면 생략한다.
4. **분류를 미룬다.** Slipbox·Resources·Project 중 어디로 갈지는 주간 검토에서 결정한다.

## 절차

### 1. 한 줄 hook 만들기

입력에서 가장 가까운 표현을 골라 파일명에 쓸 hook으로 삼는다. 멋진 제목으로 바꾸지 않는다.

파일명은 `<짧은 hook>.md`로 만들고 `/ \\ : # ^ [ ] |`를 제거한다. 같은 이름의 파일이 이미 있으면 `date '+%H%M%S'`로 확인한 초 단위 시각을 파일명 끝에 붙여 구분한다.

### 2. Quick Capture 작성하기

`date '+%F %H:%M'`으로 시각을 확인한다. 작성 전에 정본인 `99_Templates/quick-capture.md`를 끝까지 읽고, Templater 표현을 확인한 현재 날짜·시각으로 치환해 같은 구조를 사용한다. 스킬에 템플릿 전문을 복제하지 않는다.

- `created`, `tags: [inbox]`, `next_action: ""`를 유지한다.
- `## 원문`에는 오타와 명백한 음성 인식 오류만 교정한 사용자 원문을 쓴다.
- 출처가 없으면 `## 출처 / 링크`를 생략한다.
- `## AI 생성`은 템플릿의 접힌 `AI의 초기 해석 · 검증 및 채택 전` callout 안에 작성한다. 필요하면 분석 뒤에 발전 질문을 덧붙인다.
- 사용자가 원문만 저장해 달라고 했거나 의미 있는 보충이 없으면 `## AI 생성`을 생략한다.
- 다음 액션과 정리 가이드는 템플릿 문구를 유지한다.
- 본문이 한 줄뿐이어도 원문이나 AI 보충을 억지로 늘리지 않는다.

### 3. 열고 보고하기

가능하면 다음 명령으로 노트를 연다.

```bash
obsidian open path="00_Inbox/<파일명>.md"
```

생성 경로와 한 줄 hook만 짧게 알린다. 연관 노트 검색, QMD 갱신, 자동 커밋은 하지 않는다.

## 경계

- 외부 URL 자체의 저장·클리핑은 `capture-reference-card`, 읽은 자료에 대한 반응 정리는 `literature-note`를 사용한다. URL이 생각의 출처일 뿐 저장 대상이 개인 단상이면 이 스킬을 유지한다.
- 이미 충분히 정제된 생각이어도 사용자가 단순 저장만 요청했다면 Inbox에 둔다.
- 사용자가 즉시 영구 노트화를 명시했을 때만 `permanent-note`로 넘긴다.

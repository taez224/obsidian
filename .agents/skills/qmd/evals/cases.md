# 실제 질문으로 검색 확인

검색 범위나 질의 절차를 바꿀 때 [search-cases.json](search-cases.json)의 네 질문을 QMD MCP `query`로 실행한다. 이 파일은 `qmd bench` 전용 입력인 `../qmd-eval.json`과 구분한다. 일반 검색 때마다 읽거나 실행하지 않는다.

## 비교 방법

1. 질문마다 `searches`, `intent`, 기대 파일을 결과 확인 전에 정한다. 기대 파일은 현재 원문이 질문에 답하는지 읽고 선택하며, 검색 순위가 높다는 이유로 바꾸지 않는다.
2. 같은 QMD·모델·질의·`limit`·`candidateLimit`·`rerank`로 변경 전후를 비교한다. 색인 갱신이 필요하면 승인 후 먼저 기존 범위를 갱신해 기준 결과를 얻는다. 검색 범위를 바꾼 뒤 같은 입력으로 다시 실행한다.
3. 각 사례의 핵심 파일 순위와 상위 15개에 섞인 `excluded_prefixes` 경로의 수를 센다. 결과의 `qmd://` 및 컬렉션 접두사를 제거한 vault 상대 경로로 비교한다. 핵심 파일이 `expected_in_top_k` 안에 없거나 제외 경로가 남으면 실패다.
4. 상위 후보 원문을 MCP `get`·`multi_get`으로 읽고 각 사례의 `check`를 확인한다. 검색 성공을 답변 정확성으로 자동 간주하지 않는다. 최종 답변에서는 질문에 필요한 노트·대목만 보여 준다.
5. 보조 컬렉션을 명시했을 때 작업 기록과 Archive 자료를 각각 찾을 수 있는지도 확인한다. 범위를 생략한 기본 검색에 보조 컬렉션이 끼어들지 않는지 확인한다.

## 판정과 보관

순위와 혼입 수는 이 질문·모델·현재 자료에서의 관측값이다. 검색 점수를 진실성·품질 점수로 해석하거나 몇 사례의 통과를 전체 검색의 보장으로 보고하지 않는다. 평가 중 다른 실패를 발견하면 질의의 기대 파일을 쉽게 찾는 쪽으로 바꾸지 말고, 범위·원문·검색 방식의 원인을 확인한다.

고정 입력만 이 폴더에 둔다. 원시 결과·설정 백업·비교 보고서는 `_workspace/qmd-search-YYYY-MM-DD/`에 두고 `_workspace/README.md`의 수명 정책을 따른다. 형식 검사만 실행했다면 검색 평가를 통과했다고 쓰지 않는다.

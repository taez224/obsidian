# 🚦 Slop Gate — anti-slop 통찰 게이트

> 사용자가 발행 전 최종 검수를 요청했을 때 `blog-review-polish` 전체 워크플로를 돌리기 전에
> 사람이 판단하는 체크리스트다. 일반 초안·부분 윤문·기본 검수에는 사용하지 않는다.
> 근거: AI 글의 시그니처는 "표면은 매끄럽지만 아래가 빈" 상태. 이 게이트는 그 빈 곳을 검사한다.
> 분업: *표면*의 기계적 슬롭(금지표현·문장부호)은 `blog-slop-lint.mjs`가 결정론으로 걷어내고,
> 이 게이트는 lint가 못 보는 저자의 판단·근거·장르 적합성을 사람이 본다.

## 통과 규칙

고정 점수나 모든 항목 통과를 요구하지 않는다.

- 6번의 기계 검사와 7번의 출처 정직성은 모든 발행 글에서 확인한다.
- 1·2번은 경험을 근거로 내세운 글에 적용한다.
- 3·4·5번은 조어·통념 반박·강한 POV가 실제 글의 역할일 때만 적용한다.

적용 항목에서 중요한 공백이 발견되면 사람이 보완할지, 글의 범위를 줄일지 결정한다. 형식을 맞추려고 장면·조어·반론을 만들지 않는다.

## 체크리스트

```
□ 1. [경험 기반 글] 구체적 장면·사례가 있는가
     - 추상 주장마다 실제 장면(PR 리뷰, 장애 상황, 실제 커맨드/프로젝트명)이 붙는가
     - "추상론 → 추상론"으로만 이어지면 실패

□ 2. [경험 기반 글] 1인칭 체험·실패담이 들어갔는가
     - "내가 X하려다 사실 Y였다" 류의 정직한 시행착오가 있는가
     - 남 얘기·일반론만 있으면 실패

□ 3. [해당할 때] 이 글만의 조어 또는 통념 재정의가 있는가
     - 현상에 새 이름을 붙였거나(이해 부채/워크슬롭/흡수), 익숙한 말을 다시 정의했는가

□ 4. [해당할 때] 통념에 대한 반례·긴장이 있는가
     - "다들 A라 하지만 실은 B" 같은 긴장. 한쪽 주장만 나열하면 실패
     - (research 단계에서 반례를 의무 수집했는지 확인)

□ 5. [해당할 때] 강한 1문장 POV가 도입부에 있는가
     - 이 글의 칼끝(angle)이 초반에 박혀 있는가. 결론까지 미루면 실패

□ 6. [공통] "표면 매끄러움" 문장을 제거했는가
     - 빼도 의미가 같은 일반론·미사여구·트렌드 name-drop을 솎아냈는가
     - 기계 선검사: blog-slop-lint.mjs를 돌려 high를 0으로 만들고 medium을 검토했는가
       (금지표현·문장부호 — `anti-slop-lexicon.md` 기준. manifesto의 Robotic Detector를 로컬 대체)
     - 음독 테스트: 소리내어 읽어 손발이 오그라들거나 걸리는 곳이 없는가 (토스 라이팅 원칙)

□ 7. [공통] 선행글 재탕·날조가 없는가
     - 선행글은 [[wikilink]] 참조만 했는가(장면 재서술 X)
     - 소스에 없는 사건·수치를 지어내지 않았는가
```

## 확인 후

- 적용한 항목과 남은 위험만 발행 검수 결과에 보고한다.
- `slop_check` 같은 별도 점수·상태 속성을 자동으로 추가하지 않는다.
- 저자가 보완하기로 한 항목만 초안에 반영하고 전체 구조를 체크리스트에 맞춰 재작성하지 않는다.

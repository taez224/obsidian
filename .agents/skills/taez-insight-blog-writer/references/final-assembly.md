# Final Assembly — 발행 직전 다중 관점 사인오프

> 사용자가 `final-assembly`, `완전 최종 어셈블`, `페르소나 패널 최종점검`을 명시했을 때만 사용한다.
> 일반 리뷰를 매번 패널 검토로 키우지 않는다. 목표는 많은 의견이 아니라 독립된 관측을 교차해 남은 결함을 좁히는 것이다.

## 시작 조건

- 초안이 끝까지 존재하고 구조 검토가 한 번 이상 끝났을 것
- 목표 독자와 발행면을 알 수 있을 것
- 원고 수정 권한과 검토 요청을 구분할 것. 검토 요청만 받았으면 파일을 수정하지 않는다
- 이전 리뷰를 좌석 프롬프트에 섞지 않는다. 필요한 계약·근거는 조정 단계에서만 사용한다

조건이 안 맞으면 `light` 또는 구조 검토로 낮춘다.

## 좌석

원고와 목표 독자만으로 판단할 수 있는 좌석은 서로 격리한다. 사실 검증 좌석에는 필요한 근거 원장만 추가한다.

| 좌석 | 보는 것 | 적용 |
| --- | --- | --- |
| 냉소적 시니어 동료 | 현학, 인용 과밀, 사례의 무게, 설계 실수 미화 | 기본 |
| 30초 스키머 | 제목·부제·헤딩·문단 첫 문장만으로 서는 골격 | 기본 |
| 글쓰기 편집자 | 문장 리듬, 추상 명사, 종결, 음독 시 걸림 | 기본 |
| 회의적 반대자 | 가장 강한 반론을 steelman하고 글이 견디는지 | 기본 |
| 한국어 AI-티 감별사 | 번역투, 공식 문형, 요약강박, 헤지, 과교정 | 기본 |
| 트렌드 감수자 | 최신 담론의 현재성, name-drop, 출처와 저자 주장 경계 | 시의성 있는 담론·유행을 쓸 때 |
| 사실 정확성 센티넬 | 수치, 기술 인과, 연구 귀속, 반사실, 편집 델타 | 경험·기술·연구 주장에 맞춰 범위를 정함 |
| 처음 읽는 독자 | 원고 전체의 한 줄 논지, 첫 정지점, 제목과 착지 | 기본 |

가용 에이전트가 부족하면 좌석을 순차 실행하거나 한 에이전트에 서로 다른 턴으로 맡긴다. 좌석이 실패하거나 생략되면 결과에 밝히고, 실행하지 않은 좌석의 판정을 지어내지 않는다.

## 결정론적 게이트

좌석과 별개로 다음을 직접 확인한다.

1. `blog-structure-scan.mjs` — 절 비중·반복·밀도 관측
2. `blog-slop-lint.mjs` — high/medium/low와 밀도
3. `git diff --check` — 편집 회귀
4. frontmatter, 링크, 표, 이미지 임베드 — 발행 형식 무결성
5. 논지를 운반하는 도식이 있으면 `visual-argument-review.md`에 따라 실제 발행 폭으로 렌더
6. 수치·연구·기술 주장은 1차 자료 또는 근거 원장과 대조

스캐너와 좌석 투표는 사실 근거를 이기지 못한다.

## 조정 규칙

- 같은 문제를 독립된 두 좌석 이상이 잡으면 우선순위를 올리되, 그것만으로 객관적 결함이라 부르지 않는다
- 사실 불일치, 제목 약속 위반, 의미 중복처럼 근거가 분명할 때만 `객관적 결함`으로 올린다
- 한 좌석만 잡은 문제는 근거가 없으면 `편집상 위험` 또는 `취향`으로 둔다
- 글의 장르와 집필 계약에 어긋나는 처방은 다수 의견이어도 기각한다
- 외부 개념·기술 상세·유보 문단을 추가해 모든 반론을 닫으려 하지 않는다
- 이미 닫힌 쟁점은 새 사실이나 실제 회귀가 있을 때만 다시 연다
- 보존 문장은 좌석 두 곳 이상이 고르거나 글의 장면·판단·비용을 고유하게 운반할 때 확정한다

조정자는 `채택 / 기각 / 보류 / 이미 닫힘`과 근거를 남긴다. 패널의 원문을 이어 붙여 최종 보고서로 만들지 않는다.

## 종료 기준

- 구조·사실 블로킹이 0개이거나 글 안에서 미확인 범위가 정직하게 한정됨
- 제목·핵심 개념·착지가 같은 방향으로 읽힘
- 기계 검사와 실제 렌더에 새 회귀가 없음
- 남은 지적이 국소 편집 또는 저자 취향뿐임

전체 패널은 기본 한 번만 실행한다. 이후에는 새 사실이나 승인된 수정으로 생긴 회귀만 국소 재검토한다.

## 보고 형식

1. 처음 읽고 남은 주장 한 문장
2. 실제 실행한 좌석과 실패·생략 좌석
3. 발행 준비도: `ready / minor / needs-work`
4. 교차 확인된 실제 블로킹 최대 3개
5. 선택 수정 최대 3개
6. 기각하거나 이미 닫은 주요 의견
7. 보존할 문장 3~5개
8. 구조·lint·사실·도식 게이트 결과

사용자가 반영을 승인하면 선택된 항목만 패치하고, 의미 변경 영향 범위를 대조한 뒤 관련 게이트만 다시 실행한다.

## 반영 후 닫기

패널의 평가는 검토한 원고 버전에만 유효하다. 사용자가 수정을 승인하면 다음을 따른다.

- 패치 전 `반영 / 보류 / 손대지 않음` 항목을 짧게 확정하고, 그 범위 밖의 제안은 함께 고치지 않는다.
- 제목·핵심 개념·정의·헤딩이 바뀌면 [[structural-review#의미 변경 영향 범위]]에 있는 산출물 중 존재하는 것만 현재 파일과 대조한다.
- 마지막 의미 변경 뒤에는 현재 원고를 처음부터 한 번 읽고, 오탈자·띄어쓰기·링크·용어 불일치 같은 객관적 copy 결함만 고친다.
- 패치 뒤에는 실제로 바뀐 항목과 남긴 항목을 함께 보고한다.
- 새 사실 또는 구조 변경이 없으면 전체 패널은 다시 열지 않는다. 패치 뒤의 판정은 재대조한 현재 원고를 기준으로 보고한다.

# 검토 결함 장부

블로그 글을 검토하면서 기존 검사(lint, 구조 스캔, 체크리스트)가 놓친 문제를 기록한다. 객관적 오류와 독자 이해 문제를 구분하고, 당시 편집 선택을 보편 규칙으로 만들지 않는다. 아래의 선택 사항·철회 기록은 판정 근거를 보존하기 위한 것이며 규칙 승격의 근거로 세지 않는다. 글마다 정한 생략 범위나 표시 방식은 그 글의 문서 계약에서 관리한다.

## 쓰는 법

1. 실제 문제를 발견했을 때 추가 후보를 보고한다. 검토 요청만으로 장부를 자동 수정하지 않는다.
2. 관찰한 현상과 판정, 글의 유형·약속을 구분한다. 객관적 오류가 아닌 편집 선택은 새 결함으로 추가하지 않고, 기존 기록의 오판이 확인되면 재분류한다.
3. 반복 횟수만으로 승격하지 않는다. 다른 글과 요청에서도 같은 문제가 생기는 조건을 확인하고, 재사용 가능한 원인과 필요한 수정 범위가 분명할 때만 규칙 후보로 삼는다.
4. 규칙을 바꾼 뒤에는 해당 사례와 별도의 정상 사례로 확인한다. 문제를 잡으면서 정상 원고에 불필요한 수정을 요구하지 않는지도 본다.

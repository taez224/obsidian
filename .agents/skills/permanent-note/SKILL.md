# permanent-note — 메모를 제텔카스텐 permanent 노트로

사용자의 메모를 `01_Slipbox/`에 스키마 준수 permanent 노트로 생성하고, 완료 후 Obsidian에서 연다.

## 원칙

1. **원문은 사용자의 언어다.** 오타·비문만 교정하고 내용·논지·어휘 선택은 바꾸지 않는다. permanent 노트의 정체성은 "자기 언어로 정제됨"이고, 이 요건은 입력 시점에 이미 충족되어 있다 — AI가 문장을 다듬을수록 그 정체성이 희석된다.
2. **AI 기여분은 격리한다.** AI가 덧붙이는 모든 내용은 `## AI 생성` 섹션 안에만 둔다. 원문과 AI 생성이 섞이면 나중에 어느 문장이 사용자의 생각이었는지 알 수 없게 된다.
3. **연관 링크는 확신 있는 것만.** LLM 링크 제안의 ~30%는 부적합하다는 실측 경고가 있다. 연관 이유를 한 줄로 설명할 수 없으면 넣지 않는다. 링크 0개가 억지 링크 3개보다 낫다.

## 실행 절차

### 1. 제목 생성

메모를 짧은 한 문장으로 요약해 제목으로 삼는다. 제목이 곧 파일명이다.

- 파일명에 쓸 수 없는 문자 `/ \ : # ^ [ ] |` 는 제거하거나 자연스럽게 대체
- `01_Slipbox/<제목>.md`가 이미 존재하면 덮어쓰지 말고 사용자에게 확인

### 2. 연관 노트 검색

`mcp__qmd__query`로 lex+vec 두 유형을 조합해 검색한다. `intent`를 반드시 포함할 것.

```
searches=[
  {type: "lex", query: "<메모의 핵심 키워드>"},
  {type: "vec", query: "<메모의 핵심 주장을 문장으로>"}
], intent="<이 메모가 다루는 주제 설명>"
```

상위 후보 노트를 **실제로 Read해서** 연관성을 판단한다. 검색 점수만으로 넣지 않는다. 노트당 1~3개가 적정이다.

### 3. 노트 작성

오늘 날짜는 `date +%F`로 얻는다 (기억에 의존하지 않는다). 주제 태그는 CLAUDE.md 태그 체계에서 1~2개 추론한다. 아래 템플릿을 정확히 따른다:

```markdown
---
created: <오늘 YYYY-MM-DD>
tags:
  - <주제 태그>
  - slipbox
type: permanent
status: seedling
---

## 원문

<오타·비문만 교정한 메모>

## AI 생성

<보충 설명, 반례, 확장 아이디어, 추천 자료>

## 연관된 노트

- [[노트명]] - 어떤 맥락에서 연관되는지 (한 줄)
```

연관 노트가 하나도 없으면 리스트 대신 `아직 연관 노트 없음`을 남기고, 사용자에게 Slipbox 최소 1링크 규칙 위반 상태임을 알린다 (이후 vault-lint가 감시한다).

### 4. Obsidian에서 열기

```bash
obsidian open path="01_Slipbox/<제목>.md"
```

`obsidian` CLI가 없으면 macOS URI 스킴으로 폴백한다 (경로는 URL 인코딩):

```bash
open "obsidian://open?vault=obsidian&file=01_Slipbox%2F<인코딩된 제목>"
```

둘 다 실패하면 생성된 노트 경로만 안내한다.

## 완료 보고

생성한 노트의 경로, 추론한 태그, 연관 노트 개수(와 각 연관 이유)를 사용자에게 요약한다. 자동 커밋은 하지 않는다 — 커밋 여부는 사용자 판단.

# Permanent note

개인 메모를 나중의 글과 판단에 재사용할 수 있는 자기 완결적 주장으로 정제한다. 새 파일 생성보다 기존 생각의 발전을 우선한다.

## 원칙

1. **승격은 포착과 다르다.** 사용자가 영구 노트 또는 Slipbox 승격을 명시했을 때만 실행한다. 단순 캡처는 `capture-fleeting-note`로 보낸다.
2. **한 노트에는 한 중심 생각을 둔다.** 서로 독립적으로 재사용할 주장만 분리한다. 한 생각을 억지로 여러 파일로 쪼개지 않는다.
3. **완성된 글이 아니라 다시 생각할 수 있는 주장으로 쓴다.** 분량을 미리 정하지 않는다. 중심 주장만으로 명료하면 1~2문단도 충분하지만, 원래 대화나 자료를 다시 보지 않고 이해·재사용하는 데 배경·논리·적용 경계가 필요하면 그만큼 정리한다.
4. **사용자의 언어를 본문으로 삼는다.** 오타와 비문은 고치되 논지와 어휘를 임의로 전문 용어로 바꾸지 않는다.
5. **AI는 필요한 맥락을 정리하되 빈 섹션을 기계적으로 채우지 않는다.** 사용자 입력·원본 메모·확인된 참고자료에 설명·예시·반례가 있고 주장을 독립적으로 이해하는 데 도움이 되면 적극적으로 정리한다. 근거 없이 내용을 발명하거나 형식을 채우기 위한 질문을 만들지 않으며, 자료 밖의 확장 아이디어는 적용 보고에서 후보로만 제안한다.
6. **태그는 소재보다 쓰임을 우선한다.** 기존 태그 체계 안에서 이 생각을 나중에 어떤 맥락에서 다시 찾을지 기준으로 주제 태그 1~2개만 고른다.
7. **조회 경로는 승격할 때 설계한다.** 제목과 다르게 다시 찾을 가능성이 큰 사용자 표현만 `aliases`로 0~2개 제안한다. 빠른 포착 단계에는 이 판단을 요구하지 않는다.

## 절차

### 1. 중심 주장과 경계 정하기

- 메모를 한 문장 주장으로 재진술한다. 이 문장이 제목 후보이자 노트의 중심이다.
- 예시·근거·반례가 같은 주장을 설명한다면 한 노트에 둔다.
- 독립적으로 인용하고 발전시킬 수 있는 주장이 둘 이상이면 분리 후보를 먼저 제안한다.
- 외부 자료의 사실 요약만 있고 사용자의 해석이 없다면 영구 노트로 꾸미지 말고 `literature-note`를 통한 Resources 보관을 제안한다.
- Quick Capture의 `AI 생성`은 사용자 입력으로 간주하지 않는다. 사용자가 명시적으로 채택한 내용만 본문 후보로 사용하고, 확인되지 않은 외부 사실은 출처 검증 전까지 발전시킬 질문으로 분리한다.

### 2. 기존 노트와 대조하기

검색 실행 방식은 `qmd` 스킬을 따르되, 결과는 `01_Slipbox/`로 좁힌다. 찾는 것은 이 주장과 **같은 결론, 이어지는 주장, 반대되는 관점**이며, 단순한 주제 일치보다 실제 주장 관계를 우선한다.

`rg` 후보와 QMD 후보를 병합한 뒤, snippet이 아니라 상위 후보 원문을 읽는다. 다음 중 하나를 선택한다.

- **같은 주장**: 새 노트를 만들지 말고 기존 노트 보강을 제안한다.
- **이어지는 주장**: 새 노트를 만들고 관계를 한 줄로 설명해 연결한다.
- **반대되는 주장**: 충돌 지점을 설명할 수 있을 때만 연결한다.
- **단순 키워드 일치**: 연결하지 않는다.

기존 노트 수정과 새 노트 생성 사이에 의미 있는 선택이 필요하면 적용 전에 사용자에게 확인한다.

### 3. 노트 작성하기

`date +%F`로 생성일을 확인하고 `99_Templates/_property-schema.md`를 따른다. 제목은 주장형 문장으로 짓고 파일명 금지 문자 `/ \\ : # ^ [ ] |`를 자연스럽게 제거한다. 같은 파일명이 있으면 덮어쓰지 않는다.

기본 형식은 다음처럼 가볍게 유지한다.

```markdown
---
created: <YYYY-MM-DD>
tags:
  - <재사용 맥락을 나타내는 태그>
  - slipbox
type: permanent
status: seedling
aliases:
  - <제목과 다르게 떠올릴 검색 표현. 없으면 필드 생략>
---

# <중심 주장>

<사용자의 언어로 정리한 핵심 생각과 필요한 맥락. 이 부분만 읽어도 이해하고 다시 생각을 이어갈 수 있어야 한다.>

## 연관된 노트

- [[관련 노트]] - 어떤 관계인지 한 줄로 설명
```

- 본문에는 주장을 독립적으로 이해하고 재사용하는 데 필요한 만큼 쓴다. 1~2문단으로 충분할 수도 있고, 실제 배경·논리·적용 경계를 보존하려면 더 길어질 수도 있다.
- `## 설명과 예시`, `## 출처`, `발전시킬 질문`은 실제 입력·근거와 노트의 필요에 따라 추가한다. 모든 섹션을 갖추는 것을 완성 조건으로 삼지 않는다.
- 짧아도 명료하고 의미 있는 링크가 하나 있으면 `seedling`으로 충분하다. 적합한 링크가 없으면 억지로 만들지 않고 그 상태를 보고한다.
- `aliases`는 키워드 목록이 아니다. 사용자가 실제로 쓴 표현이나 다시 검색할 가능성이 큰 자연스러운 대체 제목만 둔다.
- 새 노트는 기본적으로 `seedling`이다. 길이나 링크 수만으로 상태를 올리지 않는다. 근거·반례·적용이 추가되거나 실제 글과 판단에서 재사용되면 `growing`을 검토한다. `evergreen`은 반복 검토와 안정적인 재사용이 확인돼도 자동 판정하지 않는다.
- 연관 노트 개수·관계 설명 기준은 `AGENTS.md`의 "Linking Best Practices"를 따른다. 링크가 없으면 그 상태를 보고한다.
- 참고노트에서 발전한 주장은 `AGENTS.md`의 출처 정밀도에 따라 블록·헤딩·문서 링크를 선택한다. 필요한 block ID는 참고노트의 해당 블록에 안정적인 영문 kebab-case로 추가한다.

### 4. 원본 처리하기

- Inbox 메모를 승격했다면 영구 노트를 만든 뒤 원본의 삭제·보관 후보를 보고한다. 자동 삭제하지 않는다.
- Books·Articles·Clippings에서 생각을 추출했다면 원본 Resources 노트는 유지하고 영구 노트에서 출처로 연결한다.
- 원본 전문을 Slipbox에 복제하지 않는다.

### 5. 열고 보고하기

가능하면 다음 명령으로 노트를 연다.

```bash
obsidian open path="01_Slipbox/<제목>.md"
```

생성 또는 보강한 경로, 중심 주장, 태그 선택 이유, 연결과 원본 처리 후보를 요약한다. 자동 커밋하지 않는다.

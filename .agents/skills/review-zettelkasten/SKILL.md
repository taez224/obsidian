# Review Zettelkasten

포착된 메모와 참고 자료를 다시 읽어 생각으로 발전시키는 의미 기반 정원 관리 workflow다. `vault-lint`의 기계적 헬스 검사와 역할을 분리한다.

## 원칙

1. **자동 적용하지 않는다.** 먼저 후보와 이유를 제시하고 승인된 변경만 수행한다.
2. **전문을 옮기지 않는다.** Resources의 책·아티클·클리핑은 참고노트로 유지하고, 재사용할 자기 주장만 별도 permanent note로 압축한다.
3. **새 파일보다 기존 생각의 성장을 우선한다.** 같은 주장이 있으면 합치거나 보강한다.
4. **연결에는 관계를 쓴다.** 같은 키워드가 아니라 근거·적용·반례·상하위 관계를 한 줄로 설명한다.
5. **원자성은 수단이다.** 독립적으로 재사용할 수 있을 때만 분리하고, 한 생각을 템플릿에 맞추려고 쪼개지 않는다.

## 1. 검토 범위 정하기

사용자가 파일이나 폴더를 지정하면 그 범위만 본다. 범위가 없으면 다음 순서로 제안한다.

1. `00_Inbox/_inbox.base`의 7일 이상 체류 노트
2. 사용자가 최근 읽은 Books·Articles·Clippings
3. `01_Slipbox/_index.base`의 seedling 또는 연결이 약한 노트

소규모 검토는 대화에서 처리한다. 후보가 6개 이상이면 `_workspace/zettelkasten-review-YYYY-MM-DD/report.md`에 임시 리포트를 만들고 7일 수명 규약을 적용한다.

## 2. 각 노트의 역할 판정하기

| 입력 | 기본 위치 | 판정 기준 |
| --- | --- | --- |
| 순간적인 개인 생각 | `00_Inbox/` | 아직 맥락이 부족하면 유지, 가치가 없으면 삭제, 재사용 가능한 주장이 생기면 승격 |
| 책 전체 독서 기록 | `30_Resources/References/Books/` | 책 메타정보·인용·읽으며 든 생각을 유지하고 permanent note 후보만 추출 |
| 아티클·클리핑 | `30_Resources/References/Articles/` 또는 `Clippings/` | 단순 요약은 Resources에 남기고 `my_take`와 독립 주장 여부를 확인 |
| 프로젝트에만 필요한 메모 | `20_Projects/<project>/` 또는 프로젝트 링크 | 일반화할 학습이 있을 때만 별도 permanent note 생성 |
| 자기 완결적 주장 | `01_Slipbox/` | 새 permanent note 또는 기존 노트 보강 |
| 링크 군집의 안내도 | `01_Slipbox/`의 `type: hub` | 서로 다른 permanent note 3개 이상과 반복적인 탐색 필요가 있을 때만 생성 |

## 3. 생각 후보 추출하기

각 입력에서 다음을 구분한다.

- 원자료가 말한 사실·주장
- 사용자가 동의하거나 반박한 부분
- 기존 경험과 연결한 해석
- 다른 글에서도 재사용할 수 있는 독립 주장

사용자의 해석이 없는 외부 요약을 permanent note로 승격하지 않는다. 대신 `my_take` 또는 독서 메모 보강을 제안한다.

## 4. QMD로 기존 생각과 대조하기

후보 주장마다 structured query를 직접 작성한다.

```text
intent: 이 후보와 같은 주장, 이어지는 주장, 반대되는 주장인 현재 Slipbox 노트를 찾는다. 40_Archive와 _workspace는 제외한다.
lex: <제목·핵심어·동의어>
vec: <후보 주장의 자연어 표현>
hyde: <후보가 영구 노트라면 들어갈 예상 문단>
```

상위 후보 원문을 가져와 읽은 뒤 다음처럼 분류한다.

- `새 영구 노트`: 독립적이고 기존 노트에 없는 주장
- `기존 노트 보강`: 결론이 같고 새 사례·반례·근거가 있음
- `연결만 추가`: 서로 다른 주장이지만 관계가 명확함
- `참고노트 유지`: 출처 맥락을 벗어나면 의미가 약함
- `보류`: 사용자의 해석이 더 필요함
- `삭제`: 다시 쓸 정보나 생각이 없음

## 5. 승인 제안하기

다음 형식으로 묶어 제안한다.

| 원본 | 제안 | 대상 또는 제목 | 이유 | 원본 처리 |
| --- | --- | --- | --- | --- |
| `<path>` | 새 영구 노트 / 보강 / 연결 / 보관 / 삭제 | `<note>` | 한 줄 | 유지 / 삭제 후보 / 프로젝트 흡수 |

제목과 핵심 주장 초안도 함께 보여준다. 적용 전에는 파일을 만들거나 옮기거나 삭제하지 않는다.

## 6. 승인된 항목 적용하기

- 새 영구 노트와 기존 노트 보강은 `permanent-note`의 작성 원칙과 `99_Templates/_property-schema.md`를 따른다.
- Books·Articles·Clippings 원본은 유지하고 permanent note에서 출처로 연결한다.
- Inbox 원본은 승격 후에도 자동 삭제하지 않는다. 승인 항목에 원본 처리가 포함된 경우에만 삭제하거나 보관한다.
- 링크는 `## 연관된 노트`에 1~3개 추가하고 관계를 한 줄로 쓴다.
- `seedling → growing`은 내용과 연결이 실제로 늘었을 때만 변경한다. `evergreen`은 자동 판정하지 않는다.
- 구조 노트는 설명문을 억지로 채우지 않고 링크 군집과 탐색 순서를 중심으로 작성한다.
  형식은 `99_Templates/hub-note.md`를 따른다 (frontmatter `type: hub`).
- 적용 후 QMD 색인 갱신은 사용자가 함께 요청했거나 대규모 변경일 때만 실행한다.

## Vault-lint와의 경계

- `vault-lint`: 죽은 링크, frontmatter, 고립 노트, MOC 공백 같은 기계적 상태 점검
- `review-zettelkasten`: 메모의 의미를 읽고 승격·병합·발전·구조화를 판단

두 작업을 함께 요청받으면 `vault-lint`로 상태를 확인한 뒤 이 스킬로 의미 판단을 수행한다.

# Sweep Site Worklog

작업 이력은 커밋 로그의 축약본이 아니라 사이트 구성이 지금 모습인 이유를 뒷받침하는 근거 목록이다. 커밋 수십 건을 갈래로 묶어 하루에 한 줄이나 두 줄만 남긴다.

## 대상

| 항목 | 값 |
| --- | --- |
| 소스 | `~/Projects/taez224.github.io`의 Git 이력 |
| 출력 | `30_Resources/Development/Concepts/생각의 정원을 만들고 배포하는 과정.md`의 `## 작업 이력` |

- vault 저장소의 커밋은 소스에 넣지 않는다. 이 노트는 사이트 구성을 다루므로 사이트 저장소만 읽는다.
- 사이트 저장소는 근거로 읽을 뿐 수정하지 않는다.
- 다른 노트에 작업 이력 절을 새로 만들지 않는다.

## 1. 커밋 수집

날짜 인자는 기본이 오늘이고, `YYYY-MM-DD` 하루나 `YYYY-MM-DD YYYY-MM-DD` 범위를 받는다.

```bash
cd ~/Projects/taez224.github.io
DAY=$(date +%F)   # 특정 날짜를 요청받으면 그 값을 넣는다
git log --since="$DAY 00:00" --until="$DAY 23:59:59" --pretty=format:'%h %s'
git log --since="$DAY 00:00" --until="$DAY 23:59:59" --pretty=format:'=== %h %s' --stat
```

- 커밋이 없으면 항목을 만들지 않고 그 사실을 보고한다.
- 커밋 메시지만으로 범위가 모호하면 diffstat에서 바뀐 디렉터리를 확인한다. 개별 diff는 꼭 필요할 때만 읽는다.
- 아직 커밋하지 않은 변경은 완료된 작업으로 보지 않는다.

## 2. 갈래로 묶기

1. 결과가 같은 커밋을 한 갈래로 모은다. 하나의 목표를 여러 커밋으로 나눈 경우, 예를 들어 타입 전환이나 테스트 이관은 갈래 하나다.
2. 갈래는 셋에서 넷까지만 남긴다. 더 많으면 노트를 읽는 사람에게 구성 변화로 읽히는 것만 고른다.
3. 다음은 버린다. 커밋 해시와 건수, 바뀐 파일 개수, 되돌린 커밋, 오타·서식 수정, 의존성 잠금 파일 갱신.

## 3. 항목 문안

형식은 `- **YYYY.MM.DD** ` 뒤에 명사형 나열이며, 한 줄이나 두 줄로 40자에서 80자 사이를 유지한다.

- 파일명·설정 파일·속성 이름은 백틱으로 감싼다. 굵게 쓰는 것은 날짜와 모델명뿐이다.
- 기존 항목과 같은 굵기를 유지한다. 사용자가 직접 쓴 기준 예시는 다음과 같다.

```markdown
- **2026.09.12** TypeScript 적용, Node 26 버전 변경. `DESIGN.md` 추가, 홈 최근 글 배치와 JSON-LD 구조 정리.
```

- 문장의 결은 `.agents/guides/writing.md`를 따른다. 목록 항목이므로 명사형 종결을 쓴다.
- 같은 날짜의 항목이 이미 있으면 새 줄을 만들지 않고 그 줄에 합칠 문안을 제안한다.

## 4. 누적 상한

- 일자별 항목은 최근 10개까지 둔다.
- 10개를 넘기면 가장 오래된 항목들을 주 단위나 주제 단위로 묶은 압축 후보를 새 항목과 함께 보고한다. 날짜를 묶는 형식은 기존 `- **2026.09.07~08**` 항목을 따른다.
- 압축은 사용자 승인 후에만 적용한다. 승인 없이 오래된 항목을 지우거나 고치지 않는다.

## 5. 보고와 적용

보고는 수집 범위, 갈래 요약, 제안 문안, 압축 후보 순으로 짧게 한다. 제안까지 마치면 완료로 본다.

적용 승인을 받으면 다음을 지킨다.

- 편집 직전에 노트를 다시 읽는다. 사용자가 이미 직접 쓴 항목을 덮어쓰지 않는다.
- `## 작업 이력` 목록의 맨 위에 항목을 넣는다.
- frontmatter `updated`를 항목 날짜로 갱신한다.
- 다른 절의 설명은 고치지 않는다. 구성이 바뀌어 본문 설명이 틀렸다면 후보로만 보고한다.

## 기계 확인

- 추가한 wikilink가 있으면 대상 노트의 존재를 확인한다.
- `git diff --check`를 실행한다.

## 다른 스킬과의 경계

- 세션 트랜스크립트로 하루·주·월 DevLog를 쓰는 작업은 `devlog`다.
- 프로젝트 허브의 현재 상태와 남은 일을 갱신하는 작업은 `sweep-project-context`다.
- 노트의 절 구성이나 개념 설명을 다시 쓰는 작업은 `development-note`다.

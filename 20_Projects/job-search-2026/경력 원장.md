#### Vizend QRA - GitOps 배포 오케스트레이션·런타임 모니터링 플랫폼

- 기간: 2026.01.29 ~ 2026.05, 이후 Gallery 통합 확장
- 배경과 목표: Gallery에 있던 배포 실행·관측 기능을 독립 서비스로 분리하고, 구독 요청부터 GitOps 변경, ArgoCD/Kubernetes 관측, 결과 집계와 런타임 모니터링까지 하나의 플랫폼으로 구축
- 내가 맡은 책임: 프로젝트 리드, 서비스 경계와 아키텍처 설계, 백엔드 핵심 흐름 구현, 운영 프론트엔드 구현, 이슈·ADR·검증 체계 운영
- 직접 한 일:
  - Gitea·ArgoCD·k3d 기반 로컬 PoC와 QRA 멀티모듈 구조 설계
  - Gallery 구독 이벤트 → GitOps mutation → ArgoCD sync → Kubernetes stabilization → 결과 집계 파이프라인 구현
  - 중복·충돌 요청 구분, Superseded 전이, Batch Dispatch Lease, 서버 재시작 관측 복구, Outbox·leader election 적용
  - SharedInformer/cache 재편, Kubernetes Event on-demand enrichment, SSE 런타임 모니터링 구현
  - qra-view의 배포 모니터링, SubscriptionStatus, 리소스 토폴로지, Manifest/Diff, GitOps·Registry 관리 UI 구현
  - QRA 기능을 Gallery로 재통합하고 Flyway·이벤트·내부 호출 경계를 새 구조에 맞게 정리
  - runtime Secret 암호화 저장·Kubernetes 실체화, ArgoCD PreSync DB provisioning, label 기반 cleanup과 full-lifecycle E2E 확장
- 함께한 사람·조직: 팀 구성과 역할 분담 확인 필요
- 결과:
  - 구독 요청부터 배포 실행, 상태 관측, 결과 통지까지 전체 lifecycle 구현
  - 운영자가 배포 진행, 런타임 상태, Kubernetes 리소스와 실패 원인을 확인할 수 있는 UI 제공
  - 독립 QRA의 핵심 역량을 Gallery에 재통합하고 Secret·DB 준비까지 자동화 범위 확장
- 확인 가능한 근거:
  - qra-backend Git 이력과 코드·테스트
  - vizend-monorepo의 qra-view 커밋과 현재 gallery-view 계보
  - gallery의 QRA migration, ADR-019, runtime Secret, DB provisioner, cleanup, E2E 커밋
  - [[vizend-qra|Vizend QRA]]와 2026-W05~W12 주간 회고, 관련 DevLog
- 당시 제약:
  - GitOps·ArgoCD·Kubernetes·Kafka·DB에 걸친 비동기 상태 정합성
  - 서비스 분리 후 다시 Gallery로 통합되는 제품 경계 변화
  - Secret value를 Git·이벤트 payload에 포함하지 않아야 하는 보안 경계
  - 외부 DB 자산의 삭제 정책이 확정되지 않아 runtime cleanup과 data retention을 분리해야 함
- 관련 자료·노트: [[QRA 프로젝트 정리]], [[성과 사례]], [[gallery-qra-resume-summary]]

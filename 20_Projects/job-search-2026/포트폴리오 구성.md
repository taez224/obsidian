## How I Build - AI와 함께 일하는 방식

정본은 [[AI 개발 운영체계]]를 사용한다. 별도의 AI 데모를 추가하기보다, QRA라는 실제 시스템을 만들면서 AI의 결과를 어떻게 프로젝트의 판단과 검증 근거로 바꿨는지 보여준다.

도입부에는 **Hive → QRA → Gallery**의 변화를 짧게 배치한다. Hive에서는 대화형 설계·리팩터링 보조와 초기 `CLAUDE.md` 수준이었다. QRA에서는 이를 요구사항·이슈·구현·리뷰 workflow로 체계화했고, Gallery에서는 저장소 특성에 맞게 재설계해 실제 lifecycle E2E와 MR 책임 장치까지 연결했다. 완성된 체계만 보여주는 것보다, 한계를 발견하고 개선한 판단 과정을 함께 보여준다.

| 단계 | 보여줄 산출물 | 전달할 역량 |
| --- | --- | --- |
| 의도 정제 | 요구사항 인터뷰 결과, 완료 조건, EPIC·이슈 구조 | 모호한 요청을 구현 가능한 문제로 바꾸는 능력 |
| 맥락 제공 | `AGENTS.md`, 경로별 규칙, ADR, 도메인 문서 | 암묵지를 실행 가능한 기준으로 만드는 능력 |
| 구현 | 작은 diff, 상태 모델, 이슈별 결과물 | 생성 속도를 리뷰 가능한 변경 단위로 통제하는 능력 |
| 검증 | 다른 모델의 리뷰, 단위·통합 테스트, full-lifecycle E2E | AI의 설명이 아니라 실제 실행 결과로 확인하는 태도 |
| 인수인계 | Risk/Rollback, Reviewer Guide, AI Provenance | 사람이 확인한 범위와 복구 시작점을 명확히 하는 책임감 |
| 학습 | DevLog, 회고, 실패를 반영한 규칙·명령 | 개인의 시행착오를 재사용 가능한 지식으로 바꾸는 능력 |

> [!important] 핵심 메시지
> AI를 많이 사용했다는 이야기가 아니다. 실제 플랫폼 프로젝트에서 AI가 만든 결과를 팀이 판단하고, 이유를 따라가고, 문제가 생기면 복구할 수 있는 변경으로 만드는 운영체계를 설계했다는 이야기다.
